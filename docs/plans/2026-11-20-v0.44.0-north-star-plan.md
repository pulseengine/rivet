# rivet v0.44.0 plan against the North Star (draft, awaiting owner approval)

Status: work in progress. Nothing here is approved, built or tagged. The North
Star and its objectives (O1 to O5) live in pulseengine.eu `data/north-star.toml`.

How this was made: a planner agent (claude-fable-5-2, fresh context) read the
North Star, rivet's coverage, the v0.44.0 scope, open issues, the v0.43.0 notes
and the seams, and read wohl's bundle scripts in source. A second, cold checker
(claude-fable-5-2, given only `north-star.toml` and the draft) confirmed,
refuted or could not verify each bet. This version applies its findings. The
draft requirements are REQ-419 to REQ-422 in `artifacts/requirements.yaml`,
status `draft`, `release: v0.44.0`; each description names its objective.

## Where rivet starts

- O2 is 1 of 2: wohl's release bundle passes its verify command; relay has no
  bundle. The rivet part of wohl's bundle is checked only for "file present and
  parses as JSON", so a trace at 0% coverage, or from another commit, passes.
  wohl builds rivet from source at a git ref, not from a release binary.
- O3 is unmeasured. rivet's Kani, Verus, Rocq and trust-ledger jobs are not in
  CI Gate's `needs`, so rivet would not count. The ledger has 3 rows; its
  scanner excludes `kani::assume`, of which `rivet-core/src/proofs.rs` has 29.
  rivet, spar and loom keep three ledger formats.
- `serves:`: v0.43.0 shipped `allowed-values-severity`, but no repo, rivet
  included, declares `serves` yet (seam #1296).

No bet below raises an objective's count through rivet alone, except bet 2a,
which makes rivet itself count for O3.

## Bet 1: the trace part of the evidence bundle can fail (O2 guard) — REQ-419

Ships `rivet review verify <snapshot> --commit <sha> --coverage <file>` (coverage
mandatory) on top of `rivet review export` (REQ-416). wohl can install a release
instead of building rivet from git: static musl Linux binaries already ship
(release.yml since #1086; v0.43.0 carries x86_64 and aarch64 musl archives),
though REQ-393 still reads `proposed`.

- Indicator: O2 stays 1 of 2. The guard moves: a third negative control, a trace
  from another commit with the manifest re-hashed, goes red for wohl, where it
  passes today.
- Acceptance: non-zero exit on four fixtures (another commit, empty snapshot,
  edited coverage, commit field edited without re-hashing the manifest), zero on
  the untouched bundle; the musl binary runs `review verify` in an `alpine`
  container; wohl's third control goes red.
- Kill: first check that wohl's `review export` is non-empty (it covers only
  artifacts with `release:`). If it needs a whole-project mode, that is a second
  requirement; drop the bet if wohl cannot use it. Checked 2026-11-20: wohl
  has one artifact with `release:` (v0.8.0), so the whole-project mode is
  needed and is part of this bet.
- Dependencies: new seam issue rivet/wohl for the evidence trace; wohl changes
  `verify.sh` step 3 and its release workflow; pulseengine.eu adds the third
  control to `north-star-o2.py`.
- Absorbs REQ-416, REQ-374 (#995, the tool-version record only); REQ-393 (#980)
  needs only its status brought up to date against #1086. Size M.

## Bet 2a: rivet's own proofs are a required check (O3 indicator) — REQ-420

The only bet that moves an indicator as worded: rivet's four proof jobs join
CI Gate's `needs`, and the ledger counts every `kani::assume`.

- Indicator: rivet goes from not counted to counted for O3, once pulseengine.eu
  has an O3 indicator script (O3 stays "unmeasured" until then).
- Acceptance: a failed or skipped proof job turns CI Gate red; the ledger lists
  exactly the scanner's `kani::assume` uses (29 at planning time) plus the
  existing rows; four separate probe PRs each turn CI Gate red (an `Admitted`
  without a row, a `kani::assume` without a row, a broken proof, a new axiom
  caught by the kernel audit). Stretch: remove at least 3 `kani::assume` uses,
  which is real movement on the guard ("may only shrink").
- Kill: make the Rocq dependency fetch hermetic first (it times out fetching
  from GitHub today). If Rocq still fails for infrastructure reasons in more
  than 1 of the last 10 main runs, keep it out of `needs` and say so.
- Dependencies: none outside rivet for the gate; pulseengine.eu for the count.
- New requirement. Size M; the 29 new ledger rows are the awkward part.

## Bet 2b: one ledger format other proof repos can run (O3 enabler) — REQ-421

`rivet check trust-ledger --base <ref>` fails when an entry is added, passes
when entries are removed, and emits JSON counts by kind with input-narrowing
assumptions as their own kind. It replaces the compare half of
`tools/ci/trust-ledger.py`; no new Python.

- Indicator: none directly. It lets spar, loom and relay enforce the O3 guard
  the same way.
- Acceptance: fixtures for an added entry (non-zero exit), a removed entry
  (zero) and the JSON kind counts.
- Kill: drop the shared format if neither spar nor loom adopts it by the
  2026.12 layer.
- Dependencies: new seam issue rivet/proof repos for the ledger format.
- Size S to M.

## Bet 3: declared oracles run, and the traceability gate can go red (enabler) — REQ-375, REQ-389

Relabelled from an O3 bet to an enabler after the check: no objective count
moves. The `close-gaps` dispatcher runs every declared oracle's command or
exits non-zero reporting it as not run (9 of 11 are skipped silently today, and
6 of their commands do not exist).

- Acceptance: the oracle count per schema is pinned in a test, and any removal
  is listed in the CHANGELOG; fixtures where a failing oracle and an unrunnable
  oracle each give a non-zero exit; a probe PR adding an unlinked implemented
  requirement turns CI Gate red.
- Rescope trigger: if more than one of the six missing commands needs more than
  a day of new analysis, ship "report as not run, exit non-zero" and move those
  implementations to v0.45.0.
- Dependencies: consumers on the aspice and iso-26262 presets will see new
  failures; the CHANGELOG names the affected oracles.
- Size L. The WASM render tests that skip themselves move out of this bet.

## Bet 4: features declare the objective they serve (enabler) — REQ-422, REQ-318

rivet declares `serves` on `feature` with allowed values O1 to O5 at error
severity, plus the per-repo drift check `north-star.toml` asks for.

- Acceptance: `serves: [O9]` fails `rivet validate` with an error naming the
  allowed values; `serves: [O2]` passes; a CI check fails when the allowed
  values differ from `north-star.toml` at a pinned ref.
- REQ-318 (externally-owned verification, #800) is held: built only after a
  named relay artifact that would use it is recorded in the seam issue.
- Dependencies: #1296 (pulseengine.eu).
- Size S for `serves`; M for REQ-318 if it goes ahead.

## Not attempted, and why

- O5 (rivet as a signed WASI component under kiln): not attempted. The checker
  points at a cheaper first step: a standalone ledger comparator from bet 2b
  could be the first gate built as a component, and rivet could list its own
  tools and gates for O5's denominator. Candidate for v0.45.0.
- O1: rivet has no lever on hardware runs.
- O4: installable musl binaries (bet 1) and a labelled ready queue may shorten
  time to first pick-up; not measured, so not claimed.
- relay's bundle: needs witness to read component modules (2027-Q1 stretch).
- The Q4 O2 commitment also needs a sigil release; rivet cannot move that.
- Owner exclusions kept: no refactors before 2027-02-01 (#1143), nothing to
  crates.io, no CI path classifier in rivet, no new Python.
